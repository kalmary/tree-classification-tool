Two decisions you should know about

1. RGB views are (H, W, 3); grayscale stay (H, W). This contradicts the option A I recommended last turn. Reason: the committed test asserts view.shape == (64, 64), which fixes the grayscale contract at 2D — honouring it was worth more than shape uniformity. So phase 4's pdf_writer needs the ndim branch (option B). One line: np.stack([v] * 3, axis=-1) when v.ndim == 2.

2. RGB replaces the depth shade entirely — a coloured pixel is the nearest point's raw colour, not that colour dimmed by distance. That's the literal reading of workplan p.4 ("the rgb values are used to colour the depth maps instead"), and it keeps species colour undistorted for the human classifier. The cost is that RGB views lose the depth cue that makes grayscale views readable as 3D. If you'd rather keep shading, it's colours[visible] * shade[visible, None] — say the word.

One deliberate deviation from the phase-1 contract: render's resolution is int | None = None (None → the configured resolution) rather than the protocol's int = 256. Both the constructor and render carry resolution because the committed test passes it to both; a sentinel is the only honest way to say "use my configured value". This widens the accepted input, so any protocol-typed caller passing an int is unaffected.
